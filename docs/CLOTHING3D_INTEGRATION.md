# Clothing3D in this repository

`Clothing3D/` is Saja's clothing module (fitting room and Dress3D), added with `git subtree` from
https://github.com/Saja-Khalil/-clothing-3d (branch `main`, commit `db690ac`). Her commit history is kept.
Her `Clothing3D/README.md` describes the module; `Clothing3D/reports/` holds an audit of it written on
2026-10-17 (see "Corrections to the reports" below).

## Layout

```
Project_Workspace/
  backend/, frontend/, docs/   Baraah's avatar module (avatar API :8002, avatar page :5173)
  var/generated/<id>.glb       avatars written by the avatar API (runtime, ignored by Git)
  Clothing3D/                  Saja's clothing module
    backend/server.py          fitting room :8010  (reads ../var/generated/<id>.glb)
    viewer/index.html          fitting-room page
    dress3d-prototype/         Dress3D app :8765
```

The fitting room reads avatars from the folder above `Clothing3D/` (`backend/server.py`:
`ROOT.parent / "var" / "generated"`). In this layout that is `var/generated/` at the repository root, which is
the avatar API's default output folder, so the two connect without extra settings.

**Which avatar code is active:** the avatar module at the repository root (`backend/`, `frontend/`).
`Clothing3D/newavatar-changes/` contains older proposed copies of avatar files (`api.py`, `App.tsx`, ...) kept
as part of Saja's history. Do not edit them expecting the avatar page to change.

## Running Clothing3D

From `Clothing3D/` (commands as in `Clothing3D/reports/RUN_AND_TEST_GUIDE.md`):

```
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r dress3d-prototype\requirements.txt
.venv\Scripts\python.exe -m pip install rembg onnxruntime scikit-image -c dress3d-prototype\requirements.txt
.venv\Scripts\python.exe backend\server.py          -> http://127.0.0.1:8010/viewer/?avatar=<avatar_id>
```

Third-party modules imported by `Clothing3D/backend/` and `Clothing3D/dress3d/`: numpy, scipy, Pillow, trimesh,
OpenCV (`cv2`), shapely, scikit-image, rembg (+ onnxruntime; downloads its `u2net` model on first use), and
`bpy` inside Blender. There is no `requirements.txt` for the clothing backend itself; the commands above are the
recipe recorded in the audit (rembg 2.0.85, onnxruntime 1.31.0, scikit-image 0.26.0 were installed on
2026-10-17).

Dress3D app: `cd Clothing3D\dress3d-prototype\prototype\web`, `npm ci`, `npm run build`, then
`python prototype\server.py` from `Clothing3D\dress3d-prototype` -> http://127.0.0.1:8765/.

## Known limitations (not changed)

- **Blender 4.2 LTS is required** at `%USERPROFILE%\tools\blender-4.2.23-windows-x64\blender.exe`; the path is
  hard-coded in `Clothing3D/backend/template_dress.py` (line 50). Sleeved dresses, tops, skirts, trousers and
  scarves need it.
- **No test avatar:** the fitting room falls back to `Clothing3D/output/avatar.glb` when opened without
  `?avatar=`. That file is not in Git and does not exist locally either; open the fitting room with the id of
  an avatar generated by the avatar API.
- The fitting room serves its whole folder as static files and keeps `jobs/` and `uploads/` (garment photos)
  without cleanup; it is meant for local use only (`127.0.0.1`).
- `Clothing3D/tools/ui_test.py` contains paths from Saja's machine (`C:/Users/hp/...`).
- Never commit `Clothing3D/.venv/`, `jobs/`, `uploads/`, `output/` or `var/` (all ignored).
